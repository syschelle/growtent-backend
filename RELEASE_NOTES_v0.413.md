# GrowTent Backend v0.413 – Encrypted application secrets and configuration backups

- **Encryption at rest:** Add Fernet authenticated encryption for TOTP seeds (legacy and multi-admin), Pushover app/user tokens, Gromate API password, Shelly device passwords, backend HMAC keys and RTSP camera URLs (including embedded credentials). Strong independent key from `GT_DATA_ENCRYPTION_KEY`, never stored in PostgreSQL or the exported backup.
- **Safe migration:** On startup, upgrade existing plaintext secrets transactionally to prefixed ciphertext; do not re-encrypt already sealed rows. Wrong/missing keys cause startup/authentication to fail instead of revealing protected data or modifying encrypted records. New/updated values are sealed on write; API consumers and device actions receive decrypted values only internally as needed.
- **Encrypted and restorable configuration backups:** `/config/backup/export` now returns `canopyops-backup-*.encrypted.json`, a Fernet-encrypted envelope. No plaintext backup is produced. Unlike the old export, it preserves Shelly passwords and per-tent backend HMAC keys for complete restoration. Import decrypts this envelope using the **same** key; legacy plaintext backup JSON files remain importable for migration. The existing administrator step-up proof is still mandatory for export and import.
- **Deployment requirement:** Before upgrading, generate and securely store a unique Fernet key, put `GT_DATA_ENCRYPTION_KEY` in the server's `.env` and **keep it unchanged**. Both Docker Compose files require it. The application refuses startup without a key. Update of an existing database is not reversible by simply downgrading the image: keep a pre-upgrade PostgreSQL backup and the new key separately. A lost key makes encrypted database fields and backups unrecoverable.
- **Scope:** No changes to irrigation/ESP controllers, Shelly actions, VPD rules, camera visuals, pot positions or login/2FA UX. External network and browser TLS protections remain separate security layers. Database and Docker live validation remain deployment tasks.
- **Tests:** New cipher, migration/idempotency, wrong-key, encrypted backup, production camera router, HMAC compatibility and optional isolated PostgreSQL migration regressions; existing full suite and browser checks continue.
