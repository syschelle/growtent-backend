# GrowTent Backend v0.405 – Camera pot markers (DE/EN)

- In fullscreen camera preview (Original/HDR), show up to three numbered markers at **manually saved** camera-image coordinates for the currently selected tent. With “Sorten” / “Strains”, optionally show its assigned strain names; with “Töpfe” / “Pots”, toggle all markers.
- Admins can choose “Positionieren” / “Position”, move the three markers by mouse or touch, fine-adjust with arrow keys (Shift = 5%), explicitly save, or cancel without a write. Unconfigured positions are suggested only in edit mode; no automatic plant recognition or silent saving.
- Store three normalized positions in the new nullable `tents.pot_positions_json` column, scoped to the tent ID. Schema upgrade uses `ADD COLUMN IF NOT EXISTS`, preserving the existing data. Include positions in configuration backup export/import; older backups default to unplaced positions.
- New `GET /tents/{tent_id}/camera-positions` returns positions and **current** strain names. New `PUT` validates allowed coordinate range and rejects writes unless the caller has an administrator session. Guests can see markers but not position them. The controller, Shellys, watering, HMAC writes and live JPEG stream are unchanged.
- Both JSON-only analysis exports and JSON in ZIP include `pot_positions` and `pot_positions_source: "current_tent_configuration"` (three keys with `{x,y}` or null). This is **not** a historic position record.
- If at least one marker was saved and the camera is available, the ZIP additionally includes `camera-marked.jpg`, rendered from **the same original frame** at native resolution up to 16 MP, with numeric pot labels and assigned strain names. `camera_snapshot.marked` reports its status and actual dimensions. `camera.jpg` is byte-identical and `camera-hdr.jpg` unchanged. No extra RTSP request, persisted camera pixels or new controller action.
- Missing camera or missing marker positions cannot break the analysis ZIP. Detailed behavior and export schema are in `docs/analysis-export.md`.
- Validation: Python unit/regression tests; 5 existing Node JS suites; Chromium fullscreen smoke for admin/guest, DE/EN, mobile and HDR; release-notes/patch checks. Live PostgreSQL/real RTSP/Docker validation remains deployment work.
