# GrowTent Backend v0.416 – Restrict API repository access (DE/EN)

- **No full host repository bind:** Remove `./:/project:ro` from both default API Compose configurations. This prevents the running API container from seeing the live `.env` file through an unnecessary project mount. The About/Changelog page keeps working using `/app/CHANGELOG.md` already bundled with the image.
- **Project ZIP feature:** Still disabled by default. When deliberately enabled, an administrator needs to mount a separately reviewed, secret-free project copy at `/project:ro`; otherwise the endpoint returns HTTP 503. Symlinks and case-variant private filenames are excluded. Prefer GitHub release archives instead.
- **Optional numeric non-root identity:** `GT_API_RUN_AS=0:0` preserves existing data ownership by default. After backing up and validating `./data` permissions, set `GT_API_RUN_AS=10001:10001` to run the restricted API container without root. Database/go2rtc containers and runtime volumes are unchanged.
- **Build context:** Explicit `.dockerignore` excludes local `.env`/private-key files and the Docker image normalizes application-code permissions to support the opt-in numeric UID even when ZIP files have restrictive source modes.
- **Compatibility:** No new database migration or new API credentials. Existing `GT_DATA_ENCRYPTION_KEY`, trusted-proxy CIDRs and HSTS configuration remain unchanged. Camera, Fullscreen HDR, pot markers, Shelly, ESP, irrigation and VPD paths are not modified.
- **Verification:** 481 Python tests passed (10 PostgreSQL-related tests skipped locally), five JavaScript suites and CSP, XSS, 2FA, Setup, camera/HDR/pot-markers, export and GrowGuide Chromium checks passed. Static Compose/YAML validation completed. Live Docker non-root smoke tests on production directories remain mandatory before opting into non-root mode.
