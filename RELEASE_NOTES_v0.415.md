# GrowTent Backend v0.415 – Browser security headers and compatible Docker hardening

- **Enforced CSP:** All browser/API responses use a `Content-Security-Policy` with only same-origin scripts and SHA-256 hashes for **audited first-party inline JavaScript**. Inline event handlers, third-party script hosts, foreign iframe ancestors, browser plugins, and unsafe form targets are blocked. CSP hashes are generated from trusted source templates, never from untrusted rendered input.
- **Application compatibility:** The policy permits same-origin embedded dashboards, local scripts, fullscreen camera Original/HDR, canvas `data:` image zoom, local audio, 2FA, GrowGuide and stored pot markers. The remaining inline/dynamic CSS requires `style-src 'unsafe-inline'`; JavaScript does **not** have an unsafe-inline fallback. A dynamic tent filter on the Polling Errors page is now supplied through a safe HTML `data-` attribute, leaving its trusted script hash unchanged.
- **HTTP security headers:** `nosniff`, `SAMEORIGIN`, `no-referrer`, restrictive browser permissions and same-origin resource/opener policy. Headers are applied by the outermost middleware also on login, redirects, and 401/403/503 paths, in both modular and legacy FastAPI apps.
- **HSTS:** Optional `GT_HSTS_MAX_AGE` defaults to **0** to support local direct HTTP. HTTPS-only installations should configure HSTS on their Traefik HTTPS router (recommended) or set a backend max-age. Do not enable HSTS on unverified public hosts or subdomains. Proxy configurations remain flexible; `GT_TRUSTED_PROXY_CIDRS` is unchanged.
- **Docker:** API capabilities dropped, `no-new-privileges`, read-only root filesystem, dedicated writable `/tmp` tmpfs, bounded process count and no bytecode writes. Persistent `./data` remains writable. PostgreSQL and go2rtc runtime privileges are unchanged to avoid database or camera breakage. The API remains root **inside its container by default** to avoid permission regressions on existing data; opt-in numeric-UID deployment and the remaining `./:/project:ro` exposure are documented in `docs/security-deployment.md`.
- **Tests:** 475 Python tests locally passed (10 skipped without isolated PostgreSQL), five Node suites and existing Chromium UI checks. New tests verify CSP script hash coverage, headers on redirects/errors, and browser enforcement against injected scripts. Production Docker and live Traefik/ESP/Shelly/camera tests remain deployment checks.
