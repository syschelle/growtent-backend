# GrowTent Backend v0.412 – Camera preview & Shelly schedule hotfix

- **Fix camera HTTP 500 regression:** Restore `urllib.parse.quote_plus` import inadvertently removed when implementing the v0.411 secure 2FA QR flow. Both the dashboard image and fullscreen Original/HDR camera view use this function to encode the go2rtc frame URL. This fixes the `NameError` without loosening any URL validation.
- **Fix Shelly light schedule HTTP 404:** Expose the existing `/tents/{tent_id}/shelly/light/schedule` GET handler through the modular production router. It delegates to the same existing read-only function, including `refresh=true`; no schedule write, Shelly configuration or automation changes.
- **Production-route regression tests:** New `tests/test_camera_preview_modular_regression.py` exercises the actual `api/main.py` FastAPI application with a mocked LAN camera, testing normal JPEG, HDR, login requirement and guest-readable Shelly light schedule. Previously isolated preview tests injected their own `quote_plus` symbol and could not catch a missing import in the running application.
- **Security/compatibility:** Preserve v0.411 admin step-up, mandatory login, protected QR enrollment, saved camera pot positions, source validation, guest restrictions, and existing export content. No database migration, ESP/Shelly control change, watering logic change or hardware operation.
- **Deployment:** Rebuild/redeploy the API image. Browser cache clearing cannot fix a server-side `NameError`. Confirm the new image is running, test `/tents/<id>/preview` as an authenticated user, and verify the Shelly light schedule endpoint.
- **Verification:** Python, JavaScript, browser/regression suites and ZIP/patch validity per `TESTING.md`; real go2rtc, PostgreSQL and Traefik verification remain deployment-specific.
