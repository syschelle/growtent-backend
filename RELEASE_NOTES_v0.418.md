# GrowTent Backend v0.418 – Configurable 0.90 kPa VPD for drying

- **New:** When the existing per-tent VPD automation is enabled, entering drying (`currentPhase=3`) applies a single **0.90 kPa** target by default. The Drying value is adjustable in Setup → Tents → VPD automation (DE/EN); when automation is off, no write takes place.
- **Never switch grow phases automatically:** The backend reads the phase/week reported by the ESP and can write **only** `targetVPD`; it never activates flowering or drying. A prolonged vegetative phase stays vegetative regardless of how many weeks pass.
- **Longer vegetative/flowering phases:** Beyond the final configured weekly value, the VPD target remains fixed at that phase's last value. Further weeks do **not** resend the same target or override manual adjustments. The last-success week shown is the capped plan week, not a change to the ESP's current week.
- **No weekly changes during drying:** The ESP does not need to report a drying week. Backend internally tracks drying as phase 3/week 1 so it does not repeatedly change the target as weeks advance. Successful writes and manual overrides keep the v0.417 one-time/phase semantics. A plan change still prompts a fresh sync.
- **Compatible upgrade:** v0.417 plans already saved in PostgreSQL or encrypted configuration backups are accepted unchanged and default to drying target 0.90; existing vegetative and flowering values and enabled state are preserved.
- **Same safety:** Only `targetVPD` is updated through the existing HMAC-verified ESP controller path. Retry cadence, per-tent concurrency safeguards and admin permissions are unchanged. No irrigation, Shelly, temperature, phase, camera/HDR, climate-history or export-archive changes.
- **Clarification:** The drying setting is a controller target for an environment, not a living-plant VPD reference. The informative VPD reference table continues to leave drying without a physiological reference.
- **Verification:** Targeted unit/browser tests including prolonged vegetative and flowering phases and actual ESP-reported phase changes, plus full regression suite; PostgreSQL integration and live ESP verification remain deployment checks where no isolated database or ESP is available.
